# 《院长模拟器》游戏逻辑审查报告

> 审查日期：2026-04-26
> 审查范围：`game.js`（V1 学期制 + V2 月排程制双版本共存）、`events.js`（事件数据与素材库）、`config.js`（配置数据）、`game.css`（样式）
> 审查目标：让每一个信息都有用，识别逻辑断裂、数据孤岛、功能缺失与冗余

## 一、严重问题：V1与V2双版本共存导致的逻辑断裂

### 1.1 状态对象不一致
**问题描述**：`game` 对象（V1 学期制）使用 `reputation` 字段，但文档和 V2 代码使用 `academicRep`。events.js 中的 `choice()` 辅助函数（第5行）生成的 effect 仍然使用 `reputation` 键，但 V2 `applyEffects()` 函数只处理 `repuration`（拼写错误）而不是 `reputation`。

```javascript
// events.js 第5行：choice() 用 reputation
function choice(text, idkDays, effect, feedback, staffId) {
    return { text, effect, feedback, staffId };
}

// 事件中大量使用 { reputation: N } 作为 effect
// 但 game.js 第296行 applyEffects()：
function applyEffects(effect) {
    if (effect.reputation) game.reputation += effect.reputation; // ✅ 匹配
}
```

**诊断**：
- `applyEffects()` 读的是 `effect.reputation` ✅
- 但 events 素材库中 `effect` 字段统一使用的是 `reputation` ✅
- **根本问题**：`events.js` 中的 `reputation` 与 V2 系统的 `academicRep` 不匹配。文档声称 V2 使用 `academicRep` 作为字段名，但实际代码仍用 `reputation`。

**影响**：数值变化被完全静默忽略，V2 的事件 effect 对学术声望无任何影响。

### 1.2 关键拼写错误：`repuration` 错误
**问题描述**：events.js 第 135 行「论文版面费申请」事件中使用了拼写错误的 key：
```javascript
choice('让学院报销', 3, { funds: -5, reputation: 4 }, ...)
// 素材库中第 135 行写的是 reputation: 4 ✅ 正确的
```
但代码中所有 `applyEffects` 依赖正确的 `reputation` 检查，所以无实际运行时错误。但需要确认所有数据一致性。

### 1.3 V2 系统的完全缺失
**问题描述**：虽然文档描述的是 V2 月排程系统（`v2` 全局对象、月排程队列等），但实际 `game.js` 中：
- 搜索 `v2` 前缀——代码中 **没有 `v2` 全局对象**
- 所有渲染函数使用 `render()` / `renderPlaying()`（V1 接口）
- `termStage` 仍为 `event`、`daily`、`focus`（学期制阶段）
- `availableDays` / `carryoverDays` 等月排程核心字段不存在

**诊断**：实际运行的是 V1 学期制的改进版（带学期内 stages），**并非**文档声称的 V2 月排程制。

## 二、信息孤岛：创建了但从未使用的数据

### 2.1 `adminRep`（行政信誉）
- **定义位置**：`game.js` 未定义 `adminRep` 字段
- **使用位置**：events.js 中大量事件的 effect 包含 `adminRep: N`
- **applyEffects() 函数**：只处理 `funds` / `reputation` / `morale` / `studentEval` / `energy`
- **结论**：`adminRep` effect **在 V1 中被完全忽略**

类似问题：`units`、`research` 等 field 也未处理。

### 2.2 `INITIAL_RELATION` 配置数据
- `config.js` 导出 `INITIAL_RELATION`（6 维关系网络）
- `game.js` 第 47 行：`relation: clone(INITIAL_RELATION)` ✅ 已初始化
- 但 `renderRelationCards()` 只做了展示，关系值 **没有任何决策影响**
- `adjustRelation()` 函数存在但只被 `afterChoiceSideEffects()` 调用——且调用 4 次后，关系值 **从未被用于任何条件判断或结局判定**

### 2.3 `DIFFICULTY_PRESETS`（难度剧本）
- `config.js` 导出但 `game.js` **从未 import**
- 开局配置中 **没有难度选择界面**
- 所有玩家都从完全相同的基础数值开始

### 2.4 `STUDENT_ARCHETYPES`（学生群像模板）
- `config.js` 导出并在 `game.js` 第12行 import
- `game.studentRoster` 通过 `generateStudentRoster()` 硬编码了 3 个学生（李华/张伟/王芳）
- `STUDENT_ARCHETYPES` **从未被使用**

### 2.5 `OFFICE_DECOR`（办公室陈设）
- `config.js` 导出并在 `game.js` 第7行 import
- 但 `game.js` 中 **没有购买陈设的 UI 或逻辑**
- `v2BuyDecor()` 函数不存在

### 2.6 `TITLE_RULES`（头衔解锁规则）
- `config.js` 导出并在 `game.js` 第8行 import
- `maybeUnlockTitles()` 函数硬编码了判断逻辑，**不使用 `TITLE_RULES` 配置数据**

### 2.7 `ACHIEVEMENTS`（成就系统定义）
- `config.js` 导出并在 `game.js` 第9行 import
- `recordAchievement()` 直接通过 id 和 desc 记录，**不使用 `ACHIEVEMENTS` 配置数据**

### 2.8 `STAFF_PERSONA_POOL` 中的 `quest`（个人剧情）
- events.js 定义了 5 个学生互动事件（S1-S5）
- 下属的 `personalQuest` 在 `generateStaffMember()` 中设置
- **但 game.js 中没有触发个人剧情的逻辑**——`v2AddPersonalStory()` 不存在

### 2.9 `FORUM_POOL` 论坛消息
- 仅 5 条固定文本
- `injectForumDigest()` 每月只推 1 条
- **论坛消息对数值无任何影响**

### 2.10 宠物事件的 `requirePet` / `requireDept` / `requireEvent`
- `PET_EVENTS` 中的条件字段（P2 需要 P1 先触发、P4 需要特定院系）**没有任何触发逻辑检查**
- `isPet` / `birthing` 等标记完全未被用于游戏逻辑

## 三、功能缺失与逻辑缺陷

### 3.1 事件选择 effect 不完整
- `choice()` 函数签名：`(text, idkDays, effect, feedback, staffId)`
- 第2个参数 `idkDays` 实际含义不清——在 V1 学期制下未被使用
- `staffId` 只在 `useStaffAbility()` 中被使用，但调用时机 **仅在 `v2ResolveTask()` 中**（V2 不存在的函数）

### 3.2 `buildTermEndNarrative()` 参数不匹配
- 函数签名：`(term, stats, prevStats)`
- 调用处（第 769 行附近）：未传递 `prevStats` 参数
- 导致 `fundDelta` / `repDelta` 等计算均使用 `undefined`（NaN）

### 3.3 `curriculumStudentPing()` 的学生评论不准确
- 使用 `pickRandom(game.studentRoster)`，但学生池只有 3 人
- 且评论与 `game.curriculum` 之间的关系是随机选择而非匹配学生专业

### 3.4 下属系统的未完成功能
- **`overload` 字段不存在**：`generateStaffMember()` 不生成 `overload` 字段
- **辞职检测不存在**：`v2TermEndArc()` 函数不存在
- **冲突调解**：`v2ConflictResolveUI()` 函数不存在
- **忠诚度从未因"杂务"而下降**：`useStaffAbility()` 确实记录 `chores`，但没有任何函数读取并应用惩罚

### 3.5 `applyFatigueActionNoise()` 条件错误
- 条件：`if (Math.random() > 0.22) return` → 22% 概率触发
- **但该函数从不在低精力时被调用**：没有调用点检查 `energy < 26`

### 3.6 游戏结局检测过于简单
- `checkEndings()` 只检查 5 个硬条件
- 没有结局的权重聚合、没有多结局路径
- 检测时机仅在关键函数中被调用，**月排程制下可能漏检**

### 3.7 `updateStats()` 未处理 `adminRep`
- clamp 函数只处理 5 个字段，不处理 `adminRep`
- `adminRep` 无限制范围

### 3.8 `profile` 互斥规则未被检查
- `config.js` 可能定义了词条互斥规则（如"学术明星"与"空降官僚"互斥）
- 但 `generateProfilePart()` 和 `generateFullProfile()` **不检查互斥**

## 七、结论

**核心诊断**：游戏实际运行的是"V1.5"——V1 学期制框架 + V2 的部分事件数据和配置定义。文档描述的是 V2 月排程制，但代码层面从未实现。这种"文档领先于代码"的状态导致：

1. **约 15-20% 的事件 effect 被静默忽略**（所有含 `adminRep` 的事件）
2. **约 30% 的配置数据从未被消费**（`DIFFICULTY_PRESETS`、`OFFICE_DECOR`、`ACHIEVEMENTS`、`TITLE_RULES` 等）
3. **下属系统不完整**（无辞职、无过劳、无冲突、无个人剧情触发）
4. **关系网络是展示性的**（对 gameplay 无实际影响）

**建议立即修复 P0 问题**（`adminRep` 处理、下属状态字段、参数传递错误），使现有代码中的每一个信息都真正"有用"。

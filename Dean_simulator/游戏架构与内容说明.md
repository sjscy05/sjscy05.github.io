# 《院长模拟器 · 互动反馈版》架构与内容说明（V2）

（此文系手动代码比对后的精确叙述，所有数值/名称/路径均以 2026-04-27 的实际源文件为准。）

---

## 1. 项目定位

- **在线试玩**：https://sjscy05.github.io/Dean_simulator/
- **产品形态**：多文件 Web 前端文字策略模拟（H5/CSS/JavaScript ES Module），无后端、无框架依赖。
- **主题体验**：玩家扮演一名高校院系负责人，在月度循环中管理经费、学术声望、行政声望、教师士气与学生评价五大指标，通过排程与决策影响学院命运。
- **核心卖点**：
  - 事件驱动叙事，每次决策即时生成反馈文本；
  - 月度排程执行阶段提供全屏沉浸式演出（打字机、进度点、数值动画、随机事件弹窗、个人插曲）；
  - 下属人格差异与忠诚/能力双属性带来"放权 vs 亲力亲为"的决策张力；
  - 含成就系统、头衔解锁、周目点数、多结局，具备 Roguelite 基础。

## 2. 文件架构

```
index.html                           # 入口，加载 CSS 与 type="module" JS
assets/
  css/
    game.css                         # 全部样式（506行），含动画、布局、组件、字体声明
  js/
    config.js                        # 数据配置（院系、下属、课程、难度、成就、头衔等）
    events.js                        # 内容数据工厂（事件数据、评论池、createEventData()）
    game.js                          # 引擎与 UI 渲染（~1350行，核心逻辑）
    game_restore.js                  # 存档/读档/元数据持久化（localStorage 封装）
  data/
    comments.json                    # 评论素材（独立 JSON 配置，策划可编辑）
    dept-config.json                 # 院系详细配置（带描述、优劣势 SWOT）
    events-data.json                 # 固定事件 + 院系特殊事件（JSON 格式）
```

### 文件分工

| 文件 | 职责 |
|---|---|
| `index.html` | 声明 `#app` 容器、引入 CSS/JS |
| `game.css` | 像素字体声明、全局样式、页面切换动画、数值变化动效、执行阶段全屏UI、排程队列、标签页、下属卡片、消息板、弹窗/菜单、响应式 |
| `config.js` | 游戏数据常量（关系网初始值、下属模板+人格池、院系配置、培养方案、办公室陈设、称号规则、成就、难度预设、学生原型） |
| `events.js` | `choice()` 快捷构造器、学生/教师/领导评论池、通用随机事件池（GENERIC_RANDOM_EVENTS）、真实校园事件池（REAL_UNIVERSITY_EVENTS）、`createEventData()` 工厂函数（内置月主题事件和行动数据） |
| `game.js` | 状态管理（`v2` 全局对象）、渲染函数（开局向导、主游戏、执行阶段、结局、菜单/成就弹窗）、数值运算、结局判定、消息推送、排程/队列逻辑、月度执行时间线驱动 |
| `game_restore.js` | localStorage 存取（`v2SaveGame`/`v2LoadGame`/`v2MetaSave`/`v2MetaLoad`），支持存档元数据（成就、周目点数和总运行次数） |

## 4. 游戏循环（Core Loop）

1. **开局向导**（5 步）
   - Step 0：开场叙事（随机年龄词条）→ 玩家决定开始
   - Step 1：选择院系（6 选 1，看初始修正）
   - Step 2：选择培养方案（6 选 1，看每月被动加成）
   - Step 3：选择难度（标准/地狱/顺风）
   - Step 4：输入姓名

2. **游戏初始化**
   - 应用院系初始修正 → 应用难度修正 → 初始化六方关系 → 随机生成 4 位下属（角色池抽选） → 计算当月可用天数 → 渲染主界面

3. **月度经营**
   - 玩家查看信息栏（可用天数/精力）
   - 在"日常事务"标签页选日常行动加入排程队列
   - 在"重点项目"标签页选重点行动加入排程队列
   - （可选）在"下属互动"标签页与下属谈心
   - 点击"执行本月排程"

4. **月度执行阶段**（全屏沉浸式）
   - 系统构建执行时间线：
     - 开场旁白 → [日常任务] → [中间评论] → [重点项目] → [随机事件穿插] → [个人插曲（概率）] → 收尾旁白 → 特殊情况追加
   - 逐步骤 "下一步/自动继续"，每步骤含：
     - 打字机效果叙事文
     - 数值即时更新 + 浮动 Toast 动画
     - 进度点脉冲标记
   - 随机事件弹窗在时间线触发
   - 执行完毕结算当月数值变化，进行结局检测

5. **学期结算**
   - 玩家可随时"跳过剩余天数结束本月"
   - 月度结算后应用培养方案被动加成
   - 重置当月可用天数和精力
   - 进入下一月度循环

6. **游戏结束**
   - 击杀条件触发 → 立即结算结束界面
   - 或多周目自由继续至玩家不满数值做出终止决策

## 6. 内容数据详解（events.js）

### 6.1 `createEventData()` 工厂函数

每次调用按当月月份模 12 主题生成事件，月主题轮换：

| 月份 | 主题 | 示例事件 |
|---|---|---|
| 1 | 开学 | 新学期规划、课程安排冲突 |
| 2 | 教学 | 课堂质量投诉、教学评比 |
| 3 | 科研 | 基金申报窗口、实验室管理 |
| 4 | 校企 | 企业合作洽谈、实习对接 |
| 5 | 学生 | 社团活动、心态波动 |
| 6 | 财务 | 年中预算调整、报销风暴 |
| 7 | 外部 | 评估专家组进驻、媒体关注 |
| 8 | 人事 | 教师晋升、人才流动 |
| 9 | 改革 | 制度调整、管理创新 |
| 10 | 校庆 | 校庆活动、校友回访 |
| 11 | 就业 | 就业率冲刺、企业专场招聘 |
| 12 | 年终 | 年终总结、绩效分配 |

每月返回：
- `event`：主事件（标题、叙述、选项数组）
- `dailyActions`：可选的日常行动列表
- `focusProjects`：可选的重点项目列表

### 6.2 选项结构

```js
choice(text, days, effect, feedback, extra = {})
// extra 可含：staff（下属调用）、unlockDecor（解锁陈设）、relationImpact（关系影响）
```

### 6.3 评论池

三套独立评论池（各含正面/负面），执行阶段按概率插入：
- `STUDENT_COMMENTS`：学生视角
- `TEACHER_COMMENTS`：教师视角
- `LEADERSHIP_COMMENTS`：校领导/校外视角

### 6.4 随机事件池

- `GENERIC_RANDOM_EVENTS`：10+ 通用事件（教材混用、设备舆情、教师流失等）
- `REAL_UNIVERSITY_EVENTS`：真实校园事件

月度执行时从合并池中随机抽取最多 3 个，在执行时间线中以独立弹窗和面板形式插入。

## 8. 代码层可维护性评价

### 优点

- 单一状态对象 `v2` 清晰直观，便于快速迭代与持久化；
- 内容数据以工厂函数 `createEventData()` 集中管理，扩展成本低；
- 执行阶段采用时间线模型，步骤类型可插拔（narration/task/comment/personalStory/event）；
- CSS 动画与布局分离，演出效果丰富且可复用于不同步骤类型；
- 支持存档/读档、成就系统、周目点数持久化，具备 Roguelite 基础；
- 已拆分 `config.js`（数据常量）和 `events.js`（内容工厂），初步工程化。

### 局限

- 逻辑与渲染仍耦合在同一个 JS 文件中（`game.js` 约 1350 行），体量继续增大后维护成本上升；
- `v2._activeTab` 等 UI 状态与游戏数据混在 `v2` 中，存档时需过滤；
- 事件数据（`GENERIC_RANDOM_EVENTS`、`REAL_UNIVERSITY_EVENTS`、评论池等）仍硬编码在 `events.js` 中，不利于策划独立编辑；
- `index.html` 内联 CSS 存在少量重复（如 `.page-transition-in` 动画在 CSS 与 JS 中均有引用）；
- 缺少自动化测试，回归验证依赖手动试玩；
- `data/` 目录下的 JSON 文件尚未被 JS 引用加载（平行开发中的工程化尝试）。

## 9. 关键系统说明

### 9.1 月度排程机制

- 每月有 `availableDays` 天可用（含办公室陈设加成），玩家在标签页中勾选行动加入排程队列。
- 约束：必须至少 1 项日常 + 1 项重点才可执行。
- 执行时按时间线顺序处理，中间穿插评论和随机事件。
- 精力不足时谈心等操作被阻止。

### 9.2 执行阶段时间线模型

时间线步骤类型：
| 类型 | 说明 |
|---|---|
| `narration` | 旁白叙述（开场/收尾/特殊情境） |
| `task` | 排程任务执行（内容 + 数值结算） |
| `comment` | 三方评论插入（学生/教师/校领导视角） |
| `personalStory` | 个人插曲（每学期一次概率触发） |
| `event` | 随机事件弹窗（从池中抽取） |

### 9.3 下属交互

- 谈心消耗 10 精力，随机提升忠诚 3~11 点。
- 能力在任务发放时影响成功率或效果系数。
- 人格差异：不同人设的 quest 完成后可加忠诚并永久增益；flaw 在特定条件下触发负面事件。

### 9.4 结局判定

游戏在每回合结算时执行 `v2CheckEndings()`，按优先级检查以下条件：

| 优先级 | 结局类型 | 触发条件 | 结束方式 |
|---|---|---|---|
| 1 | 💰 财务危机 | `funds <= -10` | 立即结束（失败结局） |
| 2 | 😔 众叛亲离 | `morale <= 0` | 立即结束（失败结局） |
| 3 | 🎉 任期结束 | `totalMonth >= 24`（8 学期） | 正常退休（走 `v2BuildEndSummary()` 生成多段总结） |
| 4 | 🚀 高升结局 | `academicRep >= 85` 且 `funds >= 75` | 晋升副校长（成功结局） |
| 5 | 🌸 桃李满天下 | `studentEval >= 85` 且 `morale >= 75` 且 `academicRep >= 70` | 口碑满贯结局（成功结局） |

**结局处理流程**：
1. `v2EndWithMessage(msg, type)` 设置 `v2.gameOver = true`，清除执行阶段定时器
2. 更新周目元数据（`v2MetaLoad/v2MetaSave`）：`totalRuns +1`，更新 `bestScore`
3. 计算本次得分：`academicRep + adminRep + morale + studentEval + funds`
4. 渲染结局界面：展示叙事文本、最终数值统计、称号数、周目点数、最高分
5. 提供"再来一次"和"成就查看"两个出口

**任期总结生成器 `v2BuildEndSummary()`**：
根据四项指标的分段阈值（高 ≥70 / 中 ≥40 / 低 <40）生成四段文字总结，最后拼接"感谢信"收束。

### 9.5 存档系统（game_restore.js）

**存档结构**：
- 3 个手动存档槽（slot 1/2/3）+ 1 个自动存档槽（`auto`）
- localStorage key 格式：`dean_sim_save_{slot}`
- 存档时过滤以下运行时字段（不持久化）：
  - `executionMode`、`executionTimeline`、`executionStep`
  - `pendingExecutionQueue`、`pendingExecutionTimer`
  - `_execStatSnapshot`、`_activeTab`
  - `typingTimer`、`pendingPersonalStory` 等计时器/中间态
- 存档时先快照 `pendingExecutionQueue`，如果是执行中则强制 `executionMode = false` 后保存

**元数据持久化**：
- key：`dean_sim_meta`
- 内容：`{ ach: [], points: 0, bestScore: 0, totalRuns: 0 }`
- 独立于单个存档，跨周目累计
- 启动时检测 `auto` 存档是否存在，有则展示"继续上次任期"入口

### 9.6 成就与头衔系统

**成就（ACHIEVEMENTS）**：
- 3 个内置成就（`low_fund_meeting`、`all_loyal`、`admission_streak`），各带 name/desc/points
- `v2CheckAchievements()` 按月检查：遍历 ACHIEVEMENTS 数组，检查 `cond(v2, meta)` 回调
- 新解锁时：写入 `meta.ach[]`、累加 `meta.points`、推送消息 + Toast 弹窗
- 成就数据持久化在元数据中，不受存档覆盖影响
- 成就查看界面显示解锁状态（✓/○）、条件描述和点数

**头衔（TITLE_RULES）**：
- 3 个头衔（`reform`、`funding`、`beloved`），各带 cond 回调
- `v2UnlockTitles()` 按月检查：遍历 TITLE_RULES，检查 cond 回调
- 新解锁头衔存入 `v2.titles[]`，推送 `🏅 获得称号` 消息

### 9.7 菜单系统

`v2ShowMenu()` 渲染暂停菜单，包含：
- 📁 3 个保存按钮 + 3 个读档按钮（对应 slot 1/2/3）
- ◀ 返回游戏 + 🔄 重新开始（带确认弹窗）
- 菜单渲染时不影响游戏状态，返回后继续当前阶段

### 9.8 打字机效果

`v2Typewriter(text, targetId, skipBtnId, onComplete)`：
- 按 28ms/字符的速度逐字填充目标 DOM 元素
- 提供"跳过"按钮（`skipBtnId`），点击后立即显示全部文字并触发 `onComplete`
- 局部变量 `idx` 追踪进度，`v2.typingTimer` 保存定时器引用以支持中断
- 执行阶段的旁白叙述和任务反馈均通过此函数输出

### 9.9 月度结算面板

`v2ShowMonthRecap(logs)` 在执行阶段完成后渲染：
- 展示当前学期/月份
- 列出 5 项核心数值的当前值
- 学期末（每 3 个月）额外展示 `buildTermEndNarrative()` 生成的学期回顾
- 显示最近 5 条执行记录日志
- 点击"继续下一月"后 → 应用培养方案被动加成 → 执行结局检测 → 推进月份 → 渲染主界面

### 9.10 执行阶段事件管道

执行时间线由 `v2BuildExecutionTimeline()` 构建，步骤类型：

| 类型 | 元素 | 说明 |
|---|---|---|
| `narration` | 旁白 | 开场/收尾叙事，时长由月份和状态决定 |
| `task` | 排程任务 | 日常行动或重点项目，含数值结算 + 反馈文本 |
| `comment` | 评论插入 | 从三方评论池随机抽取（学生/教师/领导视角），概率触发 |
| `personalStory` | 个人插曲 | 每学期最多 1 次，概率触发（约 30%），引入下属个人剧情或彩蛋 |
| `event` | 随机事件弹窗 | 从 `GENERIC_RANDOM_EVENTS` + `REAL_UNIVERSITY_EVENTS` 池中抽取最多 3 个，在执行中以独立弹窗/面板形式穿插 |

**执行进度可视化**：
- 顶部进度点条（`.exec-progress-dot`），每类步骤有不同状态标记：`.done`（已完成）、`.current`（当前执行中）、`.event`（事件步骤）、`.comment`（评论步骤）、`.story`（叙事步骤）
- 数值浮动 Toast（`.stat-toast-up`/`.stat-toast-down`）伴随每次数值变化
- 执行阶段操作：手动"下一步"或自动继续（3 秒间隔），可随时"中止执行"

### 9.11 开局向导详解

11 步向导（state machine，`setupState.wizardStep` 驱动）：

| 步骤 | 界面 | 可选值 |
|---|---|---|
| 0 | 开场叙事（序幕） | 随机年龄词条（青年少壮/年富力强/资深稳健），点击开始 |
| 1 | 选择院系 | 6 选 1（数学/物理/计算机/文学/经管/生医），带 icon + 初始修正预览 |
| 2 | 选择培养方案 | 6 选 1（理论/应用/均衡/科研/产学/国际），带每月被动加成预览 |
| 3 | 选择难度 | 3 选 1（标准/地狱/顺风），带初始修正预览 |
| 4 | 输入姓名 | 文本输入框（`.game-input`） |

初始化时合并：院系修正 + 难度修正 → 初始化六方关系 → 随机生成 4 位下属 → 计算当月可用天数 → 渲染主界面。

向导支持"上一步"导航，不可跳过必选项。CSS 使用 `.wizard-nav`、`.wiz-label`、`.wiz-select`、`.wiz-input`、`.dept-option` 等类。

## 14. 界面与交互全览（与 `game.js` 对照）

以下为当前 **`assets/js/game.js`** 实际实现的界面流程：每一处写的「按钮 / 可点区域」均对应 **HTML 字符串里的 `onclick`**，或由 **`addEventListener`** 绑定的控件（模块脚本必须用 **`window.函数名`** 才能在浏览器内联属性里调用）。

### 14.1 技术前提：为什么向导按钮必须挂在 `window` 上

- 入口 `index.html` 使用 `<script type="module" src="./assets/js/game.js">`。**模块顶层变量**（如 `_wizardStep`）**不是**浏览器全局变量。
- 模板字符串里的 `onclick="foo()"` 会在**全局作用域**查找 `foo`。因此：
  - `onclick="_wizardStep=1"` 之类写法**无法**修改模块内的 `_wizardStep`（这是此前「开始」无效的根因）。
  - 所有向导步骤应使用 **`window.v2WizardAfterIntro`、`window.v2SelectDept`、`window.v2SelectCurriculum`、`window.v2SelectDifficulty`、`window.v2ConfirmName`**（在 `game.js` 末尾与引擎一并注册）。
- **`v2RestartNewGame()`**：`_wizardStep = 0` 后调用 `v2RenderSetup()`，用于「检测到存档」页 / 结局页 / 菜单里的 **「重新开始」「再来一次」**，避免向导步号残留在中途。

### 14.2 启动：有无自动存档（`DOMContentLoaded`）

| 条件 | 界面内容 | 可点击项 | 行为 |
|------|----------|----------|------|
| `localStorage` 中存在 `dean_sim_save_auto` | 标题「院长模拟器」、提示「检测到之前的存档」 | **继续上次的任期** → `v2LoadGame('auto')` | 读档后 **`v2RenderPlaying()`** |
| 同上 | 同上 | **重新开始** → `v2RestartNewGame()` | 向导从第 0 步重来 |
| 无存档 | — | （无此屏）直接 **`v2RenderSetup()`** | 进入向导 |

### 14.3 开局向导（`v2RenderSetup`，内部步号 `_wizardStep`）

| 步号 | 界面标题 / 内容 | 可点击项 | 行为 |
|------|-------------------|----------|------|
| **0** | 随机年龄叙事（`BACKGROUND_POOL.age`） | **开始 →** → `v2WizardAfterIntro()` | `_wizardStep=1`，重新渲染 |
| **1** | 选择院系（`DEPT_CONFIG` 六项卡片，`.dept-option`） | 任一院系卡片 → `v2SelectDept('math'|'physics'|…)` | 写入 `v2.deptType`，`_wizardStep=2` |
| **2** | 培养方案（`CURRICULUM_PASSIVE`） | 任一方案 → `v2SelectCurriculum(...)` | `v2.curriculum`，`_wizardStep=3` |
| **3** | 难度（`DIFFICULTY_PRESETS`） | 任一难度 → `v2SelectDifficulty(...)` | `v2.difficulty`，`_wizardStep=4` |
| **4** | 输入姓名（`<input id="v2NameInput">`） | **确认 →** → `v2ConfirmName()` | 校验非空 → `_wizardStep=0` → **`v2InitGame()`** |
| **异常** | 若 `steps[step]` 不存在 | — | 直接 **`v2InitGame()`**（正常流程不应触发） |

初始化 **`v2InitGame()`**：重置 `v2` 默认状态 → 保留姓名/院系/培养/难度 → 应用院系与难度初始修正 → 初始化关系 `INITIAL_RELATION` → 生成四位下属 → 寄送欢迎邮件 → **`v2RenderPlaying()`**。

### 14.4 主游戏界面（`v2RenderPlaying`）

整体容器 `.play-container`，数据来自 `v2`。

| 区域 | 内容 | 可点击 / 操作 | 行为 |
|------|------|----------------|------|
| 顶栏 | 院系名、玩家名、学期/月、总月数 | **☰ 菜单** → `v2ShowMenu()` | 替换为菜单页 |
| 顶栏 | 同上 | **🏆 成就** → `v2ShowAchievements()` | 成就列表页 |
| 统计条 | 经费、学术、行政、士气、学生 | （只读） | 数值由 `v2UpdateStats` 等维护 |
| 信息条 | 本月剩余天数、已排程天数、精力 | （只读） | `remaining = availableDays - usedDays - 队列天数` |
| **排程队列**（`.schedule-queue`） | 已加入的日常/重点项列表 | 每项右侧 **✕** → `v2RemoveQueueItem(索引)` | 从 `actionQueue` 删除并重绘 |
| **Tab** | 日常 / 重点 / 下属 | `v2ShowActionTab('daily'|'focus'|'staff')` | 切换下方内容区，记住 `v2._activeTab` |
| **日常事务 / 重点项目** | 由 `createEventData()`（见 `events.js`）提供默认列表；按钮带 `data-act-tab`、`data-act-idx` | **点击某个行动**（非内联，脚本绑定） | **`v2AddAction(type, id, title, days, effect)`**：校验天数上限后加入队列；优先 **`v2RenderQueueOnly`** 局部刷新 |
| **下属互动** | 每位下属一个谈心按钮 | 点击 → **`v2StaffTalk(索引)`** | 精力 ≥10 消耗 10，忠诚随机上升，**整页 `v2RenderPlaying()`** |
| 执行区 | **▶ 执行本月排程** | `v2ExecuteMonth()` | 需至少 1 日常 + 1 重点，且当前代码里 **`v2.currentEvent` 恒为 `null`**（见 14.9） |
| 执行区 | **⏭ 跳过剩余天数结束本月** | `v2EndTerm()` | 不进入执行演出；应用培养被动、月推进、`v2CheckEndings()`，**`v2RenderPlaying()`** |
| 下属面板 `.staff-panel` | 下属卡片；标题行 **[收起]** | `v2ToggleStaff()` | `open` 类切换（折叠面板） |
| 消息板 | 最近若干条 `v2.messages` | （只读） | **`v2RenderMessages()`** |

**菜单内存档（`v2SaveGame` / `v2LoadGame`）**：写入 `localStorage` 键 `dean_sim_save_${slot}`；存档成功会 **`v2PushMail`** 并刷新消息（若当前在主界面且 DOM 存在）。

### 14.5 月度执行阶段（`v2ExecuteMonth` → `v2RenderExecution` → `v2ExecNextStep`）

点击「执行本月排程」后：`#app` 加退场类 → 超时后快照队列、打乱随机事件池、置 **`executionMode`**，进入全屏 **`v2RenderExecution`**。

| 元素 | 含义 |
|------|------|
| **✕ 放弃执行** | `v2AbortExecution()`：确认后清除执行态，**`v2RenderPlaying()`** |
| 顶部 **统计条** | 执行中属性变化与 Toast |
| **进度点** | `executionTimeline` 步进 |
| **⏩ 跳过打字** | 打字机 **`v2Typewriter`** 绑定 |

| 概率 **突发事件弹窗** | `v2ExecShowIndependentEvent`：选一项后应用 effect，关闭弹窗后继续 |

时间线走完后 **`v2ExecFinish()`**：培养被动、称号 **`v2UnlockTitles`**、成就 **`v2CheckAchievements`**、月计数与学期推进、清空队列与执行状态、**`v2CheckEndings()`**；若未 Game Over，拆掉执行 DOM 后 **`v2ShowMonthRecap(日志)`**。

### 14.9 已知占位 / 未完全接线逻辑（阅读代码时防误解）

- **`v2.currentEvent` / `v2.currentEventResolved`**：在 `game.js` 中**始终被清空为 `null/false`**，从未赋值为进行中事件。主界面「执行」按钮条件里的 **`!v2.currentEvent`** 目前恒为真；提示里的「请先处理主事件」来自 **`v2ExecuteMonth`** 的同一判断——若未来接入「月度主题大事件」，需在此赋值并渲染选项 UI。
- **`events.js` 中 `createEventData` 的完整工厂**（含 `fixedEvents`、院系特殊事件等）与 **`game.js` 当前主循环**的衔接：主界面行动列表来自 **`createEventData()` 无参分支**返回的 `dailyActions` / `focusProjects`；大量 **固定月事件 `fixedEvents`** 在现有 **`game.js` 流程中未作为阻塞 UI 调用**（与上一条相关）。
- 文档 **§3** 若写「月份 1–12」与现行 **`month = (totalMonth % 3) + 1`（每学年三格月相）** 不一致时，以 **`game.js`** 为准。

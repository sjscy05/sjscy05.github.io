# 《院长模拟器 · 互动反馈版》架构与内容说明（V2 重构版）

## 1. 项目定位
- **产品形态**：多文件 HTML5 文字策略模拟 Demo（HTML + CSS + JS 分离架构）。
- **主题体验**：玩家扮演高校系主任/院长，在每月经营中平衡经费、学术、士气、学生评价、行政声望与个人精力，经历突发事件、下属互动、个人插曲，最终在任期结束时获得结局评价。
- **核心卖点**：
  - 事件驱动叙事 + 月度排程执行（全屏沉浸式执行阶段）；
  - 数值经营与风险管理并行，多重结局与成就系统；
  - 下属性格与忠诚影响执行效果，形成"放权 vs 亲力亲为"决策张力；
  - 打字机式逐字叙事、数值变化动画、进度点指示器，强舞台感演出。

## 2. 整体技术架构
- **架构风格**：多文件分离架构——HTML 入口 / CSS 样式 / JavaScript 引擎。
- **文件结构**：
  - `index.html`：极简入口，只挂载 `#app` 容器；
  - `assets/css/game.css`：全部样式、动画、布局、响应式；
  - `assets/js/game.js`：全部引擎逻辑（约 1350 行），含数据定义、渲染、执行、持久化；
  - `assets/fonts/`：像素字体文件（Fusion Pixel 12px Proportional SC，WOFF2）。
- **渲染方式**：基于字符串模板 + `innerHTML` 的手动渲染（无虚拟 DOM）。
- **状态管理**：单一全局变量 `v2` 作为 V2 引擎状态源（无框架、无外部依赖）。
- **模块加载**：`<script type="module">` 加载 JS（支持现代浏览器原生 ES Module）。
- **流程控制**：通过 `v2.phase` 字段进行界面分流：
  - `setup`：开局向导（5 步）；
  - `playing`：月度经营（排程 + 执行）；
  - `review`：任期结束回顾与结局；
  - `gameover`：提前结局。

## 3. 模块划分

### 3.1 入口层（HTML）
- `index.html`：定义 `<meta charset="UTF-8">`、viewport、`#app` 容器、引入 CSS 与 JS。
- 不包含任何业务逻辑，仅作为资源加载入口。

### 3.2 UI 层（展示与交互）—— `game.js`
**开局向导（5 步 Wizard）**：
- `v2RenderSetup()`：总入口，根据 `_wizardStep`（持久变量）分发步骤：
  - Step 0：随机抽取年龄词条（BACKGROUND_POOL.age），打字机展示背景；
  - Step 1：输入院长姓名；
  - Step 2：选择院系（数学/物理/计算机）；
  - Step 3：选择培养方案（理论/应用/均衡）；
  - Step 4：选择主角词条（15 个可选 + 是否禁用负面词条）。

**月度经营主界面**：
- `v2RenderPlaying()`：渲染完整主界面布局（`.play-container`）：
  - 顶部信息栏（院系名、日期、可用天数、精力值、菜单按钮）；
  - 统计条（经费、学术、行政、士气、学生评价）；
  - 左栏：故事/事件区域、排程队列、行动标签页；
  - 右栏：管理层面板（下属卡片）、消息板。
- `v2RenderActionTabs()`：渲染 3 个标签页（日常事务/重点项目/下属互动）+ 排程队列 + 执行按钮。
- `v2ShowActionTab(tab)`：切换标签页内容，动态生成可点击的行动按钮。
- `v2AddAction(type, id, title, days, effect)`：将行动加入排程队列，增量更新 UI。
- `v2RenderQueue()` / `v2RenderQueueOnly(area)`：渲染排程队列列表，支持移除项。
- `v2RenderStaffPanel()`：渲染管理层下属卡片（含姓名、职务、性格、能力、忠诚、特质描述）。
- `v2RenderStaffActions(container)`：渲染下属谈心按钮列表。
- `v2RenderMessages()`：渲染最近 8 条消息日志。

**执行阶段（全屏沉浸式）**：
- `v2ExecuteMonth()`：启动月度执行，构建时间线（开场叙事 → 任务穿插评论 → 个人插曲 → 闭幕叙事），切换至全屏执行舞台。
- `v2RenderExecution()`：渲染全屏 `exec-stage` 布局（进度点指示器、内容舞台、统计数字、操作区）。
- `v2ExecNextStep()`：逐帧推进时间线，处理 4 种步骤类型（narration/comment/task/personalStory），驱动打字机效果与自动播放。
- `v2ExecShowIndependentEvent(ev)`：弹出独立随机事件弹窗（15%概率触发）。
- `v2ExecRefreshStatValues(oldStats)`：对照快照刷新统计数字并触发 Toast 动画。
- `v2ExecFinish()`：执行结束，应用培养方案被动加成、检测成就、清理状态、返回主界面或触发结局。
- `v2AbortExecution()`：放弃执行，返回主界面。

**结局与回顾**：
- `v2CheckEndings()`：在关键节点检查即时结局条件：
  - 财务危机、众叛亲离、高升、撤并、桃李满天下。
- `v2EndWithMessage(msg)`：统一切换至 `gameover`/`review` 阶段。
- `v2ShowMonthRecap()`：每月结束后的回顾面板（统计变化、事件日志）。
- `v2BuildEndSummary()`：构建任期结束总结（含成就统计、周目点数）。

**打字机效果**：
- `v2Typewriter(text, targetId, skipBtnId, onComplete)`：逐字显示文本到指定容器，支持跳过按钮和完成回调。

**标题系统**：
- `v2UnlockTitles()`：根据条件自动解锁头衔（如"改革先锋"、"拉赞助能手"）。

**菜单系统**：
- `v2ShowMenu()` / `v2HideMenu()`：暂停菜单弹窗（继续/存档/读档/跳回首页/取消存档）。

### 3.3 规则层（数值与结局）
- **数值边界**：`v2UpdateStats()` + `clamp()`。
  - 经费（`funds`）：`[-30, 120]`
  - 学术声望（`academicRep`）、行政声望（`adminRep`）、士气（`morale`）、学生评价（`studentEval`）：`[0, 100]`
  - 精力（`energy`）：`[0, 100]`
- **月度日历**：每月可用天数 = `v2CalcAvailableDays()`（基础 22 天，受词条、疲劳等因素影响）。
- **行动队列约束**：执行前必须至少排 1 项日常 + 1 项重点（`v2ExecuteMonth` 中校验）。
- **效果应用**：`v2ApplyEffect(effect)`：统一效果入口，处理数值变更、下属忠诚变更、消息推送。
- **结局判定**：`v2CheckEndings()` 在每次 `v2UpdateStats()` 后执行：
  - 财务危机（经费 < -15）；
  - 众叛亲离（士气 < 5）；
  - 高升结局（学术 > 90 && 经费 > 70）；
  - 撤并结局（行政 < 15 && 学生 < 20）；
  - 桃李满天下（学生 > 85 && 士气 > 70 && 学术 > 65）。
- **周目点数**：`meta.points` 跨存档持久化（localStorage `v2_meta`），成就解锁时增加。

### 3.4 内容层（事件与文本）
内容数据结构均以 `createEventData()` 入口函数返回，含：

- **背景年龄词条**：`BACKGROUND_POOL.age`（15 条，含 tag + value + flavorText）。
- **主角词条**：`BACKGROUND_POOL.identity`（15 条，含起始属性修正 + 特殊效果描述）。
- **院系配置**：`DEPT_CONFIG`（数学/物理/计算机，含名称、图标、初始修正）。
- **培养方案被动加成**：`CURRICULUM_PASSIVE`（理论 +2 学术/月，应用 +2 学生/月，均衡各 +1/月）。
- **下属定义**：`STAFF_V2`（4 位下属，含姓名、职务、性格、能力、忠诚、特质文本；第四位按院系适配）。
- **日常行动池**：`createEventData().dailyActions`（教学研讨、企业走访、行政例会、学生座谈等）。
- **重点项目池**：`createEventData().focusProjects`（教学改革、重大项目、国际会议、设备采购等）。
- **通用随机事件**：`GENERIC_RANDOM_EVENTS`（教师流失、设备故障、指标调整等）。
- **真实校园随机事件**：`REAL_UNIVERSITY_EVENTS`（更多校园场景事件）。
- **校园评论池**：`STUDENT_COMMENTS`、`TEACHER_COMMENTS`、`LEADERSHIP_COMMENTS`（各含正面/负面分支，在执行过程中穿插展示）。
- **个人插曲**：`personalStory` 类型（7 个，如家人来电、深夜办公室、食堂偶遇等，每学期仅触发一次）。
- **成就定义**：`ACHIEVEMENTS`（如 low_fund_meeting、staff_loyalty_80 等，含名称与周目点数）。

### 3.5 角色层（下属系统 V2）
- `v2.staff` 维护 4 位核心下属，数据结构：
  - `name`、`title`、`trait`（性格特质）
  - `ability`（能力 1-100）
  - `loyalty`（忠诚 1-100）
  - `profile`（一段背景描述）
  - `flaw`（可选缺点描述）
- 第四位下属按院系适配：
  - 物理系：实验室主任陈刚（技术宅）
  - 数学系：计算中心主任徐睿（算法痴）
  - 计算机系：实验中心主任黄鹏（商业嗅觉）
- **下属互动**：`v2StaffTalk(idx)` 消耗精力 10 提升指定下属忠诚（随机 3~10），推消息到消息板。
- **任务执行**：`v2ResolveTask(task)` 生成带叙事反馈的执行结果文本。

### 3.6 持久化与成就系统
- **存档**：`v2SaveGame()` → localStorage `v2_save`（序列化 `v2` 对象）。
- **读档**：`v2LoadGame()` → 从 localStorage 恢复并 `v2RenderPlaying()`。
- **存档检测**：`v2HasSave()` 判断是否有可用存档。
- **元数据**：`v2MetaLoad()` / `v2MetaSave()` → localStorage `v2_meta`（`{ach: string[], points: number}`）。
- **成就 Toast**：`v2QueueAchievementToast(name, points)` 从左上角弹出成就解锁提示。

## 4. 游戏循环（Core Loop）—— V2 月度体系

1. **开局配置（5 步向导）**  
   年龄 → 姓名 → 院系 → 培养方案 → 主角词条。完成后初始化游戏状态 `v2InitGame()`。
2. **进入月度主界面**  
   显示当前月份、统计、下属卡片、消息板、行动标签页。
3. **排程阶段**  
   玩家在每日/重点项目/下属互动标签页中选择行动，加入排程队列。每月可用天数有限，需在精力约束下规划。
4. **执行阶段（全屏沉浸式）**  
   点击"执行本月排程"→ 全屏执行舞台：
   - 开场叙事 → 逐任务展示执行结果（文字反馈 + 数值动画）→ 穿插校园评论 → 可能触发随机事件弹窗 → 个人插曲 → 闭幕叙事 → 培养方案被动加成 → 成就检测。
5. **月度回顾**  
   展示统计变化与事件日志，进入下一个月。
6. **结局触发**  
   任意时刻触发即时结局条件或完成全部任期后进入 `review` 阶段。

## 5. 关键系统说明

### 5.1 初始差异化
- **年龄词条**：开篇随机抽取（35~62 岁），影响初始叙事氛围。
- **院系选择**：数学系（学术+5 经费-10）/ 物理系（无修正）/ 计算机系（经费+10 学生+5 学术-5）。
- **培养方案**：理论型（月学术+2）/ 应用型（月学生+2）/ 均衡型（各+1）。
- **主角词条**：15 条可选（学术明星、空降官僚、工科转行、海归精英等），各有起始属性修正与持续效果。

### 5.2 月度行动经济
- 每月基础可用天数 22 天（`v2CalcAvailableDays`），受词条与疲劳影响浮动。
- 日常事务消耗天数较少（1~3 天），稳定推进；重点项目消耗天数多（3~5 天），效果显著。
- 精力值影响可执行行动上限，谈心等互动消耗精力。
- 排程队列要求：至少 1 项日常 + 1 项重点方可执行。

### 5.3 执行阶段演出
- 全屏覆盖式 `exec-stage` 布局，顶部进度点指示器（圆点颜色区分：done/current/event/comment/story）。
- 打字机逐字显示叙事文本，支持跳过按钮与 3 秒自动继续。
- 数值变化时触发 Toast 浮动动画 + 闪光效果。
- 约 15% 概率在步骤之间触发独立随机事件弹窗。

### 5.4 反馈叙事
- 事件与行动计划均有文本反馈，保证"选择—结果—情绪回路"完整。
- 执行过程中穿插学生/教师/领导三方评论，增强校园氛围。
- 文本中嵌入角色态度、组织氛围变化，增强管理模拟沉浸感。

## 8. 代码层可维护性评价

### 优点
- 单一状态对象 `v2` 清晰直观，便于快速迭代与持久化；
- 内容数据以工厂函数 `createEventData()` 集中管理，扩展成本低；
- 执行阶段采用时间线模型，步骤类型可插拔（narration/task/comment/personalStory/event）；
- CSS 动画与布局分离，演出效果丰富且可复用于不同步骤类型；
- 支持存档/读档、成就系统、周目点数持久化，具备 Rouge-lite 基础。

### 局限
- 逻辑与渲染仍耦合在同一个 JS 文件中（约 1350 行），体量继续增大后维护成本上升；
- `v2._activeTab` 等 UI 状态与游戏数据混在 `v2` 中，存档时需过滤；
- 事件数据（`GENERIC_RANDOM_EVENTS`、`REAL_UNIVERSITY_EVENTS`、评论池等）硬编码在 JS 中，不利于策划独立编辑；
- `index.html` 内联 CSS 存在少量重复（如 `.page-transition-in` 动画在 CSS 与 JS 中均有引用）；
- 缺少自动化测试，回归验证依赖手动试玩。

## 10. 建议的下一步演进方向
- **内容工程化**：将事件、角色、成就、评论池拆到独立 JSON 配置文件，JS 只保留引擎逻辑。
- **状态分层**：把"纯规则计算"（`v2ResolveTask`、`v2ApplyEffect` 等）和"DOM 渲染"解耦，提升可测性。
- **灵感落地**：将 `设定更新.txt` 中的动态叙事、角色记忆、延迟后果、办公室政治等设计实现到引擎中。
- **素材接入**：将 `素材库.txt` 中的下属词条（性格弧光、特殊事件、忠诚高低行为）、主角词条互斥/依赖规则接入数据层。
- **数值可视化**：增加月度报表（折线图/雷达图）辅助玩家理解决策后果。
- **多周目继承**：用周目点数兑换初始加成（更强下属、更多经费、隐藏情报等）。
- **体验增强**：加入难度模式、新手引导、更多成就与标题。

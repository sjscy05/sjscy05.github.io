# 《院长模拟器 · 互动反馈版》V2 架构与内容说明

## 1. 项目定位
- **产品形态**：多文件 HTML5 文字策略模拟（HTML + CSS + ES Module JavaScript）。
- **主题体验**：玩家扮演高校系主任/院长，在 8 学期（24 个月）任期内平衡经费、学术、行政、士气、学生评价与个人精力。
- **核心卖点**：
  - 排程驱动月度执行（日常事务 + 重点项目，自由组合）；
  - 全屏沉浸式执行阶段，打字机叙事 + 数值动画 + 突发事件；
  - 下属人格系统（随机生成姓名/特质/档案），可谈心培养忠诚；
  - 周目成就系统 + 称号系统 + 难度选择，提供重玩价值；
  - 存档/读档（localStorage，3 个手动槽位 + 1 个自动槽位）。

## 2. 整体技术架构
- **架构风格**：ES Module 三文件分离，HTML 单入口 `<script type="module">` 加载 `game.js`。
- **渲染方式**：基于字符串模板 + `innerHTML` 的手动渲染，辅以 CSS 动画（过渡、数值闪烁、进度条）。
- **状态管理**：单一全局对象 `v2` 作为状态源（无框架、无外部依赖）。
- **事件处理**：DOM 事件委托与直接绑定混合（按钮 `onclick` 属性 + `addEventListener`）。
- **流程控制**：通过 `gameOver` / `executionMode` / `currentEvent` 等标志位进行界面分流：
  - `setup`（向导式 5 步开局）；
  - `playing`（主经营界面，排程 + 管理层面板 + 消息板）；
  - `execution`（全屏沉浸式执行阶段，时间线驱动）；
  - `recap`（月度结算面板）；
  - `gameover/ending`（结局界面）。

## 7. 关键系统说明

### 7.1 初始差异化（院系选择）
- **数学系**：学术声望 +5，经费 -10（学术强、资源紧）
- **物理系**：无额外修正（均衡模板）
- **计算机系**：经费 +10，学生评价 +5，学术声望 -5（市场热度高、学术初值偏弱）

### 7.2 培养方案被动加成
每学期结算时自动应用（在 `v2ExecFinish()` / `v2EndTerm()` 中）：
- **理论扎实型**：学术声望每月 +1（每学期 +3）
- **应用技能型**：学生评价每月 +1（每学期 +3）
- **均衡培养**：学术 +0.5、学生 +0.5（每学期各 +1.5）

### 7.3 难度系统
| 难度 | 影响 |
|------|------|
| 简单 | 初始各项 +10 |
| 普通 | 无修正 |
| 困难 | 默认预设（可通过 init 字段配置减益） |

### 7.4 精力经济（行动上限）
- 精力是月度核心资源，默认为 100。
- 下属谈心消耗 10 精力。
- 某些日后扩展行动可能消耗精力。
- 每月结算时精力重置为 100。

### 7.5 执行阶段细节
- **时间线生成**：按 [日常...] → [重点...] 顺序排列，任务间 40% 概率插入校园评论。
- **随机事件**：从 `GENERIC_RANDOM_EVENTS` + `REAL_UNIVERSITY_EVENTS` 合并池中抽 3 个，执行中 15%/步概率弹出，弹出后从池中移除。
- **个人插曲**：每月 60% 概率触发（`termPersonalStoryUsed` 标志位控制每月仅一次），7 种随机叙事。
- **数值快照**：执行前保存 `_execStatSnapshot`，每次变动比较新旧值产生 Toast 动画与闪烁效果。

### 7.6 下属系统
- 4 位固定岗位：教学秘书、学术副主任、教务主任、实验室主任。
- 每次开局从对应人格池随机抽取（姓名、特质、能力值、忠诚值、档案文本、缺陷）。
- 谈心：消耗精力 10，忠诚随机 +3~10。
- 忠诚当前仅用于叙事沉浸，尚未在任务计算中生效。

### 7.7 结局系统（6 种）
| 结局 | 触发条件 | 类型 |
|------|---------|------|
| 财务危机 | 经费 ≤ -10 | gameover |
| 众叛亲离 | 士气 ≤ 0 | gameover |
| 任期结束 | 总月数 ≥ 24 | ending |
| 高升结局 | 学术 ≥ 85 且 经费 ≥ 75 | ending |
| 桃李满天下 | 学生 ≥ 85 且 士气 ≥ 75 且 学术 ≥ 70 | ending |

### 7.8 周目系统
- **成就**：跨存档持久化（localStorage `dean_sim_meta`），含条件检测函数。
- **称号**：当局内获得，不跨存档。
- **周目点数**：累计成就点数，可用于未来扩展（如初始 bonus 购买）。
- **最高分**：追踪历史最佳总分（五项数值之和）。

## 10. 代码层可维护性评价

### 优点
- 数据与逻辑分离（config.js / events.js / game.js）；
- 事件数据结构统一，扩展内容成本低；
- 存档/读档系统完整，支持 4 个槽位；
- 执行阶段时间线设计清晰，易于插入新步骤类型；
- 周目元数据独立持久化，为 Roguelite 设计打下基础。

### 已知问题与优化项
- ~~`v2CalcAvailableDays()` 咖啡机双重计数 Bug~~ ✅ 已修复
- ~~`v2RenderQueueOnly()` 中 `replaceWith` 导致闪烁和 Tab 跳回~~ ✅ 已修复（改为直接 innerHTML 更新）
- ~~执行后黑屏（`page-transition-out` animation fill 残留）~~ ✅ 已修复（手动重置 opacity/transform）
- `v2.typewriter` 使用 `setTimeout` 而非 `setInterval`，理论上取消更快但在极快连续调用时可能有残留回调
- 下属忠诚尚未在任务执行中生效（叙事层面的暗示 vs 实际数值计算）
- 缺少自动化测试，回归验证依赖手动试玩
- `createEventData()` 每次调用重新构建事件数据，可考虑缓存

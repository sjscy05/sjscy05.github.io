================================================================================
《院长模拟器》设定与迭代方向（优化稿）
================================================================================
说明：下文「现行」指当前原型机制；「改版」指第九节起的方向性调整，落地时需统一
      规则（例如取消「精力条」后，原「精力过低」类效果应改写为「超负荷/排期冲突」）。

--------------------------------------------------------------------------------
一、动态叙事与角色记忆（让反馈千人千面）
--------------------------------------------------------------------------------
【上下文感知反馈】
选择后的反馈不宜固定。应结合当前数值、下属状态、历史选择动态生成，以提升沉浸感。
例：教学改革后，士气<40 → 老教授当面发难；士气>70 → 表面抱怨、私下对年轻教师认可改革。

【角色记忆】
下属记住你的倾向。例：多次经教务办主任处理事件 → 其忠诚增长更快，学术主任则易感到被边缘化（忠诚隐性下降）。学期末可通过邮件/纸条流露情绪。

【延迟后果】
部分选择不立刻结算。例：校庆大办 → 当学期声望上升，约两学期后财务预警；招生「佛系」→ 远期就业率滑坡时才显现代价。

--------------------------------------------------------------------------------
二、随机与风险（不可控的魅力）
--------------------------------------------------------------------------------
【事件嵌套】
同一事件骨架下，子情境随机。例：「青年教师被挖角」——对象可能是普通讲师或嫡系；诱因可能是外校高职、创业合伙等。

【政策/环境波动】
隐藏或半隐藏变量：校领导风向、学期主题。例：本学期「本科教学优先」→ 科研类收益打折、教学类提升；下学期「双一流指标」→ 学术声望加成变化。

【小概率极端事件】
约一成概率触发高影响事件：正向（匿名捐赠、国际奖项等）；负向（实验室安全、学术不端举报等），需紧急应对。

--------------------------------------------------------------------------------
三、立体下属与关系网
--------------------------------------------------------------------------------
【性格与弧光（示例）】
· 教学主任型：老好人，忠诚易升，能力有软上限；连续在事件中担责 → 过劳病休、暂时离岗。
· 学术主任型：孤傲高能力、初始忠诚偏低；支持其冲击人才帽子 → 逐渐成为核心；长期杂务化 → 离职风险。

【个人支线】
每学期可选是否进入某下属的私人剧情（子女转学、专著出版等），完成后大幅提升忠诚并可能解锁被动能力。

【办公室政治】
下属之间存在资源/理念矛盾，你的站队影响双方满意度与隐性阵营。

--------------------------------------------------------------------------------
四、碎片化叙事与世界感
--------------------------------------------------------------------------------
【邮箱 / 内部论坛】
非主线渠道：学院八卦、匿名吐槽、校长信箱摘录。侧面描写局势；小事（食堂、吐槽院长偏科研）可间接影响学生评价或提示团建需求。

【历史彩蛋】
前任院长备忘录、老教授日记等，揭露学科评估往事、解释对改革的抵触来源。

【学生群像】
少量具名学生（学霸、创业型等），随培养倾向产生不同轨迹；毕业时来信，纳入结局评价。

--------------------------------------------------------------------------------
五、自定义与身份感
--------------------------------------------------------------------------------
【职称 / 头衔】
完成目标解锁称号（如「改革先锋」「拉赞助能手」），影响 NPC 称呼及部分选项。

【办公室陈设】
消耗经费与时间（或改版后的「日程容量」）布置办公室；陈设可影响精力恢复、访客情绪等（表现可用简约像素小图或 ASCII）。

【培养方案】
在院系大方向下微调课时、企业导师等，反馈到课程名与课堂氛围类短文本。

--------------------------------------------------------------------------------
六、多维度权衡与隐性数值
--------------------------------------------------------------------------------
【与「改版」的衔接】
若保留「精力条」：精力过低时决策可带噪声（效果浮动或小额随机负面），强调劳逸结合。
若改为「月度行动表」（见十）：则用「排期过满 / 连续加班 / 冲突截止日」替代「精力过低」，表达同一类压力。

【声望结构（可选）】
拆分为学术声望 vs 行政声望：前者利结局走向学术高层，后者利校内资源，二者难以全满。

【隐性关系】
与校领导、兄弟院系、企业、校友会等不可见条，影响事件成功率与外援选项。

--------------------------------------------------------------------------------
七、多周目与成就
--------------------------------------------------------------------------------
【继承】
新周目可用上局「经验点」兑换更强初始下属、经费或某事件的隐藏情报。

【成就】
极端玩法挑战：如经费<10 办国际会、全员忠诚>80、连续多届分数线上涨等。

【初始剧本】
难度档位：地狱开局（负债、骨干流失、抗议）与爽文开局（校长背书、资源倾斜）等。

--------------------------------------------------------------------------------
八、界面与节奏
--------------------------------------------------------------------------------
【演出】
关键剧情可选打字机式逐字显示（可跳过）。

【学期 / 学年回顾】
阶段结束生成简报：大事记、关键数据变化，附师生一句评价，强化闭环与成就感。

--------------------------------------------------------------------------------
九、时间与校历（4 年制）
--------------------------------------------------------------------------------
· 游戏周期：4 年。
· 每年 12 个月；本科生 7–8 月暑假、1 月寒假；研究生假期由导师安排（可做简化规则或事件说明）。

--------------------------------------------------------------------------------
十、行动表取代精力条（核心循环改版）
--------------------------------------------------------------------------------
· 取消单一「精力」数值。
· 每月 30 天（或抽象为「本月可用工时格」）：玩家在月初排「行动表」。
· 不同行动耗时不同；本月排不下的自动顺延至下月，下月可用时间从「上一行动结束日」起算（或采用队列+结束日规则，实现时需写清避免死锁与无限拖延漏洞）。

--------------------------------------------------------------------------------
十一、视听与信息量
--------------------------------------------------------------------------------
· 整体风格：简约像素风。
· UI 原则：单次屏幕文字量可控，长叙事拆页/折叠/日志回看，避免大段堆砌。

================================================================================
落地优先级建议（可选执行顺序）
================================================================================
1. 时间与行动表规则写清 → 再迁移事件成本、日常/重点阶段逻辑。
2. 动态反馈与记忆可先局部实现（模板槽位 + 条件分支），再扩数据库。
3. 像素 UI 与文案减量可与原型并行，减少后期返工。

1.游戏开局先介绍背景，不要直接跳到角色属性界面，先设定主角名字，然后生成一段背景介绍，再然后才是抽属性之类的
